# Ripple Live Android 温暖语音界面设计

日期：2026-08-08

状态：视觉方向、动效强度、排版、图标、主要子界面和配色均已确认

## 1. 目标

将当前 Android 语音体验从“冷色、胶囊堆叠、塑料圆盘式核心”调整为更接近 GPT Live 的舒适、紧致和灵动体验，同时保留 Ripple 的记忆、待办、视频和结构化结果能力。

本次设计采用以下最终方向：

- A2.2 紧致界面与 A2 冰云流体核心。
- B1 柔暖钴蓝为主色，加入不超过 8% 视觉占比的 B2 晨光反射。
- 稳定圆形剪影、内部多层流体、真实输入/输出能量和 4%–8% 的克制尺寸变化。
- Android APK 是唯一实现目标；iOS 代码冻结，不修改、不扩展、不重新生成。

## 2. 当前体验的问题

真机版本存在以下问题：

1. 首页核心由外圆、内圆和描边构成，像塑料按钮而不是实时生命体。
2. 大标题、宽主按钮、历史胶囊和底部导航同时争夺注意力。
3. 通话页顶部状态胶囊、字幕大框和底部控制大框形成三套互不关联的容器语言。
4. 状态主要靠文字和整体缩放表达，内部材质没有足够深度。
5. 青蓝高光叠加纯黑背景过冷，缺少 GPT Live 官方动画中的钴蓝、暖白和环境反射。
6. 图标视觉尺寸、线宽、圆角、填充方式和点击区域不统一。

## 3. 设计原则

1. **一个视觉中心**：语音页只有流体核心是主视觉，其他元素降低权重。
2. **稳定外形、内部生长**：圆形边界保持稳定，主要运动发生在内部云带、色场和高光。
3. **状态连续**：连接、聆听、思考、工具、回答和打断属于同一个连续物理系统，不切换为独立动画。
4. **紧致但可触达**：图标视觉尺寸缩小，点击区域保持 44–50px。
5. **短文案**：状态直接写“我在听”“想一想”等短语，不解释界面本身。
6. **容器按需出现**：容器只用于真实结果、回执和错误；状态、字幕与控制不套大胶囊。
7. **温暖来自高光**：暖色只存在于奶油白高光和少量晨光反射，不扩散成粉紫色产品主题。

- 单帧中暖色混合强度不高于 8%。
- 导航、主按钮、状态点和结果卡不得使用暖紫或蜜桃色作为主色。

## 5. 流体核心

### 5.1 材质

核心为边界稳定的圆形实时渲染面，内部包含三层不同速度的运动：

1. **底层色场**：钴蓝上下迁移，周期约 7–10 秒。
2. **中层云带**：低频噪声经域扭曲后缓慢对流，周期约 4–7 秒。
3. **表层高光**：奶油白高光与极少量晨光反射，周期约 3–5 秒。

不得使用同心圆描边、固定内圆、加载圆环、音频柱或大幅果冻形变。圆形边缘使用窄范围平滑透明度，不绘制独立边框。

### 5.2 状态动效

| 状态 | 尺寸和位置 | 内部运动 | 文案 |
| --- | --- | --- | --- |
| 待机 | `0.965 → 1.025`，4.2 秒呼吸 | 低速，低亮度 | “有什么想聊的？” |
| 连接 | 收紧至 `0.92–0.96` | 向心、降亮 | “正在连接…” |
| 聆听 | `0.98–1.045` | 输入能量增加局部亮度和流速 | “我在听” |
| 思考 | `0.94–0.98` | 整体减速，亮部下沉 | “想一想” |
| 工具 | 上移约 32dp，缩小至 `0.68–0.72` | 低能量持续流动 | “正在查天气”等真实动作 |
| 回答 | `0.96–1.075` | 输出能量点亮云带，停顿回落 | 默认不重复显示“正在回答” |
| 打断 | `1.04 → 0.92 → 1.0`，约 160ms | 先泄压，再恢复聆听 | “我在听” |
| 错误 | `0.92`，停止能量响应 | 降饱和但保留轻微呼吸 | “连接断开” |

尺寸变化必须使用平滑后的能量值。聆听使用快起慢落，回答使用实际播放 RMS，不能播放与音频无关的固定强动画。

### 5.3 Ripple 外围波纹

- 核心外侧常驻一层贴近球体的近场光晕，透明度约 4%–6%。光晕只随呼吸和能量轻微明暗变化，不持续向外移动。
- 事件波纹使用 B/R2 方案：每次只产生一圈柔和波纹，从核心半径约 `1.03×` 向外扩散到 `1.28×`，在 650–750ms 内完成，默认时长 700ms。
- 波纹起始透明度不高于 14%，颜色以 B1 柔亮蓝和奶油白为主；扩散时同步加宽、模糊并快速衰减，不保留清晰描边，不使用固定循环。
- 波纹与核心共用同一个 WebGL2 canvas。任何时候最多存在一圈；当前波纹未结束时出现的新事件不叠加新圈，只允许近场光晕轻微提亮。
- 全局触发冷却时间不短于 1200ms。同一段连续话语通常只触发一次，不根据每个 RMS 峰值或每个音节重复触发。
- 用户讲话只在一次有效的 `speech_started` / VAD 起音时触发；助手回答最多在一句话的首个稳定强调峰触发一次；工具结果到达时触发一次稍缓的确认波纹；打断完成后触发一次低透明度的快速波纹。
- `prefers-reduced-motion` 下取消向外扩散，只让近场光晕短暂提亮；低质量模式保留单圈扩散，但取消角向扰动和额外噪声采样。

### 5.4 性能和回退

- 使用单个 WebGL2 canvas，目标 60fps。
- 高质量模式使用 5 层噪声；低质量模式使用 3 层噪声并限制 30fps。
- 连续 2 秒低于 45fps 时降级，连续 5 秒高于 58fps 后才恢复。
- `devicePixelRatio` 上限为 2。
- WebGL 初始化或上下文恢复失败时，回退为同配色静态圆形加亮度呼吸。
- `prefers-reduced-motion` 下取消云带位移和大部分缩放，只保留亮度变化。

## 6. 排版与文案

### 6.1 字级

| 场景 | 字级 | 字重 |
| --- | --- | --- |
| 首页主问题 | 24–28sp | 560–600 |
| 普通页面标题 | 22–24sp | 580–620 |
| 实时字幕 | 15–17sp | 540–580 |
| 状态文字 | 10–12sp | 600–650 |
| 正文 | 14–16sp | 400–500 |
| 列表预览与时间 | 9–12sp | 400–500 |

字体使用系统无衬线字体栈：`Inter`, `SF Pro Display`, `PingFang SC`, `Noto Sans SC`, `system-ui`。标题字距约 `-0.04em`，正文不使用大幅负字距。

### 6.2 最终文案

| 原文案类型 | 最终文案 |
| --- | --- |
| 首页 | “有什么想聊的？” / “可以直接说” |
| 主按钮 | “开始对话” |
| 相机 | 仅图标，辅助文本“打开镜头” |
| 聆听 | “我在听” |
| 思考 | “想一想” |
| 工具 | “正在查天气”“正在搜索”等具体动作 |
| 视频状态 | “镜头已开启” |
| 错误 | “连接断开” / “重试” |

回答状态不长期显示“正在回答”；实际字幕和球体能量已经表达该状态。

## 7. 图标系统

- 使用 Phosphor 风格的圆角单线图标，不创建装饰性图标语言。
- 基础网格为 24×24，安全边距 2px。
- 统一线宽 1.65px，圆头和圆角连接。
- 顶部工具图标 18px，底部导航 20px，结果图标 22px。
- 顶部点击热区 44×44px，实时控制 50×50px。
- 未选中图标使用次要文字色；选中图标使用中层钴蓝或柔亮蓝，并在文字下增加 3px 微光点。
- 结束通话使用细线 `X`，背景使用 `--danger`，不使用厚重电话听筒图标。
- 状态优先由流体动效和颜色表达，不为“聆听”“思考”“回答”制造独立图标。

主导航图标：

- 对话：圆角消息框。
- 记忆：书签。
- 待办：圆形勾选。
- 我的：用户轮廓。

实时控制图标：镜头、麦克风、字幕、结束。默认只显示图标，文字作为无障碍标签。

## 8. 主要界面

### 8.1 对话首页

- 右上角历史入口仅显示 18px 图标，不使用文字胶囊。
- 核心位于上半屏中心，宽度约 156dp。
- 主问题位于核心下方约 38dp。
- 主语音按钮宽约 183dp、高 47dp，使用奶油白背景。
- 镜头入口为独立 47dp 圆形次级按钮。
- 四栏导航保留，但去除高亮背景块，只使用颜色和微光点。

### 8.2 语音通话

- 顶部为收起、`Ripple + 时长`、更多三个区域，不显示状态胶囊。
- 核心约 188dp，位于视觉中心偏上。
- 状态与最近一句字幕直接浮在背景上，不使用字幕大框。
- 底部显示镜头、麦克风、结束三个独立圆形按钮，不使用外层控制容器。

### 8.3 实时结果

- 核心上移缩小后，结果卡从底部以 280ms 进入。
- 结果卡使用受控类型，不渲染任意 JSON。
- 天气、搜索、图片、记忆和待办使用一致的 18–22px 单色图标。
- 结果出现时语音继续，结束按钮位置不移动。

### 8.4 视频模式

- 摄像头画面占满背景。
- 顶部结构与语音通话一致。
- 不叠加大型流体核心。
- “镜头已开启”和最近一句字幕位于控制栏上方，不使用大框。
- 底部保留镜头、麦克风、结束三个按钮。

### 8.5 对话历史

- 页面标题、圆形搜索入口、轻量搜索框和列表构成主要层级。
- 列表优先展示标题，预览和时间降低对比度。
- 右下角保留 48dp 语音浮动入口。

### 8.6 对话详情

- 助手消息不使用气泡，用户消息使用低对比度圆角块。
- 工具回执使用紧凑的受控卡片。
- 底部输入器包含附件、占位文字和圆形语音按钮。

### 8.7 记忆

- 使用双列视觉卡片；卡片图片、标题、备注和时间构成四级层次。
- “全部、置顶、图片”使用轻量筛选标签。

### 8.8 待办

- 顶部仅保留“进行中 / 已完成”两项标签。
- 时间直接显示在行尾，来源作为弱化文字。
- 完成项降低透明度并使用删除线。

### 8.9 我的

- 展示账户、服务连接、通知、语音与字幕、记忆管理、数据与权限。
- 不加入尚未真实可用的音色、智能等级、后台通话或持续视频设置。

## 9. 组件边界

现有结构继续采用以下职责：

- `ConversationHome.tsx`：首页内容和主入口。
- `BottomNav.tsx`：四栏导航和选中状态。
- `LiveOrb.tsx`：canvas 生命周期、尺寸观察、减少动态效果和回退。
- `orbRenderer.ts`：纯 WebGL 渲染，不推断业务状态。
- `motion.ts`：状态映射、能量平滑、尺寸策略、时序和质量策略。
- `LiveCallScreen.tsx`：实时排版、字幕、控制和结果托盘。
- `LiveResultSheet.tsx`：受控结构化结果卡。
- `AppNavigation.css`：首页、普通页面和导航视觉。
- `LiveCall.css`：语音、视频、流体核心、字幕、结果和控制视觉。

不得在渲染器内部复制会话状态机；业务状态仍由 `RealtimeSession` 提供。

## 10. 错误和恢复

- 连接失败：核心降饱和，显示“连接断开”和“重试”，保留结束入口。
- 相机权限拒绝：回到语音界面，显示紧凑说明和系统设置入口。
- 工具失败：结果卡显示真实失败状态，不生成成功回执。
- WebGL 失败：切换 CSS 静态核心，语音会话继续。
- 应用回前台且会话失效：返回原对话详情并保留已产生内容。

## 12. 验收标准

1. 首页没有塑料同心圆、历史文字胶囊或多套高亮容器。
2. 语音核心使用 B1 柔暖钴蓝和奶油白，B2 晨光占比不超过 8%。
3. 状态间运动连续，聆听和回答的尺寸变化分别受真实输入和输出能量驱动。
4. 回答状态最大缩放不超过 1.075，待机最大缩放不超过 1.025。
5. 核心外有 4%–6% 的近场光晕；事件波纹每次只向外扩散一圈，约 700ms 内消失，触发间隔不短于 1200ms，且不会随每个音频峰值频繁触发。
6. 通话页不再显示顶部状态胶囊、字幕大框和底部大控制容器。
7. 图标统一为 1.65px 线宽，视觉尺寸 18/20/22px，热区不小于 44px。
8. 保存记忆、创建待办和工具结果仍来自真实结果事件。
9. 相机仍只能由用户明确点击后启动。
10. Android APK 构建通过并完成真机截图与录屏验证。
11. 不修改任何 iOS 文件，不引入 Responses API 以外的 Agent API 协议。
